# Database migrations

1. Create a separate Neon development branch from production.
2. Set `DATABASE_URL` to the development branch's pooled connection string for application traffic.
3. Use a direct connection string for migration execution.
4. Generate reviewed migrations with Drizzle Kit and commit them to `drizzle/`.
5. Test migrations against development data before proposing production rollout.

Do not apply schema changes to the production branch without explicit approval. Existing `neon_auth` tables must be inspected before integrating auth; do not recreate them in the application schema.

The `0002_demo_market_symbols.sql` migration adds fictional demo-only instruments. Their illustrative quote and candle data is generated by the application and is not live market data.

The `0003_demo_only_market.sql` migration disables legacy provider-sourced assets, removes them from saved watchlists, and changes the order function's quote-source label. It preserves historical order, fill, position, and ledger rows. It has been applied to both development and production. Production had no application tables or application trading data before the schema rollout.

The `0004_demo_starting_balance.sql` migration sets the default and reset balance to $3,000. It changes only untouched legacy accounts; accounts with order, ledger, or open-position history keep their current starting balance. It has been applied to and verified on both development and production.


The `0005_progression_academy.sql` migration creates the per-user XP ledger and seeds four beginner lessons. It has been applied and verified on both development and production. Lesson quiz answers are checked server-side, completion is stored in `learning_progress`, and XP awards use a per-user idempotency key to prevent duplicate rewards.

The `0006_instrument_metadata.sql` migration adds a sector and description to each fictional asset. It has been applied and verified on both development and production.

The `0007_opt_in_leaderboards.sql` migration adds a privacy-first leaderboard profile table. Profiles are private by default, and the ranking query uses current-month portfolio snapshots rather than client-submitted returns. It has been applied and verified on both development and production.


## Verified production rollout (2026-10-22)

With explicit approval, migrations `0001` through `0007` were applied to the Neon production branch `br-icy-bonus-b4nmq99p` in order. Post-migration checks confirmed all 15 public application tables alongside the 9 existing `neon_auth` tables, 29 asset records with 17 active fictional instruments, sector metadata for all 17 active instruments, four academy lessons, the $3,000 `demo_accounts.initial_balance` default, and updated order/reset functions. The application tables were empty before rollout; this created schema and seed data only, not user accounts or trading history. Continue to require explicit approval for future production schema changes.
